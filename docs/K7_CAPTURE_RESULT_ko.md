# K7 실제 추출 자료 분석 및 시험 빌드

대상: `YGPE.KOR.0000.V039.001.260902`, 지역 폴더 `/system/onebin/ygpe_kr`.
사용자가 제공한 LEAFIA port 키트 결과를 분석했습니다. 이 문서에는 제조사 원본, 키, 비공개 로그, 개인 식별 정보를 넣지 않았습니다.

## 확인 결과

| 항목 | 결과 |
|---|---|
| 압축 검사 | 266개 항목, 압축 해제 크기 108,324,288바이트, ZIP CRC 오류 없음 |
| 차량 / 플랫폼 | YGPE 한국형, TCC897x, Android 4.4.2 / SDK 19 |
| NEMESIS | 키트에서 `nemesis_1_15_or_newer=yes` |
| 핵심 원본 9개 | 기존 한국 K5(`dl3hev`) 입력 해시와 모두 일치 |
| 차분 재구성 | 수정 APK 6개 버전과 AA 라이브러리 1개, 출력 7개 해시 모두 기존 매니페스트와 일치 |
| 프레임워크 정적 검사 | 수집한 ODEX 42개에서 클래스 18,567개 분석. 수정 APK 6개 버전의 프레임워크 멤버 오류 0개, 검사한 플랫폼 네임스페이스의 누락 클래스 0개 |
| CarPlay Core / 변환기 | 기존 레시피 기준 `NATIVE` |
| CarPlay 오디오 형식 | 기존 레시피 기준 `PATCHABLE` |
| 실제 Leafia 무선 연결 / Kia Connect | 아직 시험하지 않음 |

`HKMC_GPM`, `HKMC_DiPO`, `Iap2ServerApp`, `HKMC_Navi_ExSL`의 APK/ODEX 8개와 `libautoreceiver_infobank.so`가 같은 원본입니다. 따라서 이번에는 다른 차량의 코드를 추측해 병합할 필요 없이 검증된 동일 입력용 델타를 참조할 수 있습니다. `patches/k7pe_kr/manifest`는 `dl3hev/` 델타를 참조하며, `stock`은 K7 수집 파일과 동일한 해시를 사용합니다.

K7 등록은 **관측한 V039.001.260902 제품 문자열**에만 매칭합니다. 포크 호환성 DB의 상태는 `testing`이며 상위 프로젝트의 공식 지원 또는 실차 성공을 뜻하지 않습니다.

## build.prop 제품명 차이 처리

순정 `build.prop`에는 `KIA.KOR.0000.V039.001.260902`, 실제 실행 중 속성에는 `YGPE.KOR.0000.V039.001.260902`가 있습니다. 브랜드 공용 시스템 속성을 차종별 부팅 설정이 덮어쓰는 경우로 판단했습니다. 지역·전체 버전 접미사, `ro.build.branch`, `ro.build.version.incremental`이 일치하고 핵심 파일 해시도 일치합니다.

기존 수집 검사 도구는 이를 서로 다른 펌웨어로 오인했습니다. 브랜드 공용 접두사일 때 위의 빌드 정보가 모두 일치해야만 경고로 허용하도록 수정했습니다. 버전이 다르거나 근거 속성이 빠진 경우에는 여전히 거부합니다.

## Wi-Fi: 소프트웨어 기능 존재와 실제 작동을 구분

키트의 약 37초 가동 시점 스냅샷에는 다음이 있습니다.

- `wl: wl driver adapter not found`
- 네트워크 목록에 `wlan` 인터페이스 없음
- 핫스팟 서비스 중지
- 순정 지역 설정에서 무선 AA·CarPlay·핫스팟 기능 제거 항목 활성
- Wi-Fi 모듈 기능 XML은 있으나 이것만으로 하드웨어를 확인할 수 없음
- 수집한 커널 요약에는 SDIO 카드 인식/펌웨어 시작 증거가 없으며, 명시적인 DHD 전원 실패도 없음

이는 **현재 드라이버/인터페이스 미검출**입니다. 모듈이 물리적으로 없다는 확정 증거도, 무선 연결 가능하다는 증거도 아닙니다. 순정 설정 때문에 드라이버가 시작되지 않은 경우와 하드웨어·드라이버 문제를 아직 구분하지 못했습니다. 기존 설치기의 Wi-Fi 실패 검사는 유지하며 우회하지 않습니다.

## 모의 설치 검증과 한계

실제 수집한 순정 트리, ARM `lpatch`(QEMU), NEMESIS 1.15 환경 스텁, **bash 호스트 셸**로 검사했습니다. 이 실행은 mksh 검증을 대신하지 않습니다.

- Android 실행 상태: `INSTALL OK full mode`, 제거 후 `/system` 바이트 일치.
- Android 중지 상태: `INSTALL OK full mode`, 제거 후 `/system` 바이트 일치.
- Wi-Fi 전원 실패를 주입한 경우: 사전 설치 거부 확인.
- USB 설치 지시 파일의 이름 변경, 앱 재실행 및 Dalvik 캐시 처리 확인.

모의 Wi-Fi 인터페이스와 `dexopt`는 스텁입니다. 실차 Dalvik 검증, RF 통신, 스마트폰 페어링, 실제 계기판/HUD, Kia Connect와 OTA의 정상 동작을 보장하지 않습니다. 프레임워크 검사 역시 정적 검사이며 실제 Android 검증기 실행이 아닙니다.

## 다음 실차 단계

1. 순정 내비·Bluetooth·후방카메라·오디오와 Kia Connect 상태조회/원격 기능의 기준 상태를 확인합니다.
2. 시험용 빌드를 설치한다면 아래 [K7 안내](K7_PORTING_ko.md)의 시험 절차와 기존 제거 방법을 먼저 확인합니다. 첫 시험에는 `LEAFIA-WIFI-CLIENT` 옵션을 추가하지 않습니다.
3. 무선 연결 결과와 함께 설치 직후 port 키트를 다시 실행해 결과를 확인합니다. 연결이 안 되면 연결 시도 직후 약 1분 내 실행하여 로그를 보존합니다.
4. 모듈 존재를 확인한 방법이 부품 번호·분해 사진인지, 소프트웨어 메뉴 표시인지 구분하면 원인 판단에 도움이 됩니다. SIM/모뎀 연결은 Wi-Fi 증거가 아닙니다.
5. Wi-Fi 실패 로그가 있거나 순정 기능에 이상이 생기면 반복 설치로 해결하려 하지 말고 NEMESIS 로그를 확인하고 패키지 제거를 검토합니다.

제조사 원본과 재구성한 전체 APK는 개발용 비공개 작업 폴더에만 두었습니다. 배포 ZIP에는 기존 프로젝트 구조대로 차분 패치·레시피와 도구만 들어가며, 제조사 전체 APK나 키는 넣지 않습니다.
